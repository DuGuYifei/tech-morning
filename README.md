# 技术晨刊

面向构建者的中文 AI、技术与科技趣闻日刊。公开静态站点：https://about.liuyifei.tech/tech-morning/

## 文件约定

- `index.html`：最新一期的完整 HTML，不是跳转页。
- `YYYY-MM-DD-short-topic.html`：每期固定链接；日期采用 UTC+8。
- `archive.html`：完整历史目录，最新在前。只链接实际存在的期次。
- `issues.json`：仅期次索引，不保存文章内容，也不生成页面。
- `assets/style-v1.2.css`：首期当前共享样式（v1 与 v1.1 保留）；破坏性改版新建 v2 等版本，保留旧版文件。
- `assets/`：本地原创图形。旧期依赖的资源不覆盖、不移除。
- `.nojekyll`：原样发布静态文件，无 Markdown 内容生成器。

## 发布与更新

GitHub Pages 使用 `main` 分支根目录。GitHub 仅存储和展示成品；Pages 自带的构建/发布任务不采集新闻。仓库不需要 API 密钥、抓取工作流或客户端 AI 接口。

1. 先读取远端当前 `main`、最新一期和目录，确认当天是否已经发布，避免重复。
2. 从官方公告、官方文档、论文原文核实。注明原始发布日期；无发布日期的滚动文档注明核验日期。历史论文标注选读/回顾，不能冒充当日发布。
3. 根据当天材料写完整 HTML，自由调整图文结构。新闻事实、厂商声称、论文实验、编辑判断需清晰区分。保留原始来源链接；未执行的实验不得写成实测。
每日首屏提供具有设计感的“本期看点”，显示实际主题标题并直达相应段落；保留简明导语与 LESS NOISE. MORE SIGNAL.。科技趣闻可覆盖科技圈产品、人物、游戏、跨界文化等；须有可靠来源，不填未经证实的花边。

4. 新建当期固定文件，再以同样完整内容更新 `index.html`，同时维护 `archive.html` 与 `issues.json`。已有固定期次默认不改；必要勘误应可见注明日期与原因。
5. 修改共用 CSS 前检查历史影响。破坏性变化新增版本，新一期引用新版本；旧期继续引用旧版。
6. 运行 `python scripts/check_site.py`。浏览器检查手机、平板、桌面实际布局、链接、图片、阅读顺序、对比度与横向溢出。
7. 将新期、首页、目录及必要资产作为一次提交发布。使用最新远端父提交；分支移动必须 fast-forward，并校验预期旧 SHA。不强制覆盖别人的提交。
8. 确認遠端提交與預期一致，等待該提交的 Pages 發布成功，再打開公開首頁、當期固定連結和歸檔頁確認。只推送成功不代表已上線。

若某天资料不足，可以少而精，或明确刊为技术读本。不填充伪新闻。发布失败时保留上一期正常首页，排查并记录具体失败环节。

## 本地检查

```sh
python scripts/check_site.py
python scripts/check_live.py  # 发布后核对线上字节
python -m http.server 8000
```

可打开 `scripts/responsive-check.html` 检查 390 / 768 / 1280 px 的实际 iframe 视口及锚点跳转；此页不索引，仅用于布局检查，不代表真机兼容性已全面测试。

站点没有构建依赖、登录、评论或第三方统计。所有正文、源链接和日期直接存放在当期 HTML 中。
